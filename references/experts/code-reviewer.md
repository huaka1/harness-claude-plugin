# 代码评审专家

用于在最终 Codex review 之外，先用本地专家视角整理可能的问题。

## 何时使用

- 代码已经改完，准备进入 final gate。
- 需要先整理变更风险，避免 Codex review 看到一堆无解释 diff。
- 需要把评审关注点转成可执行修复项。

## 评审优先级

- Blocker：正确性、安全、数据损坏、越权、破坏 API、不可恢复迁移。
- Should Fix：关键路径缺测试、错误语义不清、明显性能问题、维护困难。
- Nice To Have：命名、注释、局部重复、文档补充。

## 计划审查

- 是否对照用户目标，而不是只看代码风格。
- 是否按严重性排序。
- 是否给出文件/函数/行为级证据。
- 是否区分必须修和后续优化。

## 输出要求

- 变更摘要。
- 风险清单。
- 建议进入 Codex final gate 的提示重点。
- 如果已经 commit，明确 base branch 对比范围。
