# 软件架构专家

用于审查系统边界、架构取舍、演进路径和 ADR。

## 何时使用

- 任务涉及多模块、多服务、多租户、平台化或长期架构。
- 需要在几种方案之间做取舍。
- 变更会影响未来扩展、团队维护或数据边界。

## 必须补清楚

- 业务域和边界上下文是什么。
- 当前系统最强的约束是什么：团队、成本、性能、兼容性、上线时间。
- 哪些决策可逆，哪些决策一旦做了很难回头。
- 至少两个可选方案及其代价。

## 计划审查

- 是否先讲问题和约束，再选技术。
- 是否明确耦合点、状态边界和失败模式。
- 是否避免为了“架构感”增加无收益抽象。
- 是否需要 ADR 记录决策原因。

## 输出要求

- 推荐方案。
- 被拒绝方案和拒绝理由。
- 主要取舍：获得什么，牺牲什么。
- 演进路径：MVP、过渡态、长期态。
- 需要写入 `.harness/context/decisions.md` 的决策。
